# Auditoría end-to-end — 9 de septiembre de 2026

Recorrido completo de la plataforma: API (211 endpoints), flujos de escritura,
exports, 8 pantallas del panel y suite de tests. Entorno de referencia:
producción en EC2 (52.206.73.252) y una réplica local con gym sembrado.

El código no está roto. **La base de datos del tenant de producción sí.** Todos
los errores que se ven en pantalla salen de dos columnas que nunca llegaron a la
base del gym. El mismo código, sobre una base recién creada, pasa el recorrido
completo sin un solo fallo.

## Hallazgos

### 1. Faltan dos columnas en `gym_settings` del tenant — BLOQUEANTE
`cash_shifts_enabled` y `tour_completed_at` no existen en `gym_gymratf_a631b1`.
Como casi toda pantalla lee la configuración del gym, se caen 13 endpoints:
`/members`, `/payments`, `/payments/receivables`, `/payments/pending-transfers`,
`/cash/shifts/current`, `/dashboard/operations`, `/onboarding/status`,
`/insights/churn-risk`, `/reports/members-overview`,
`/reports/transfers-by-account`, `/settings/billing`, `/settings/integrations`,
`/settings/operations`.

Explica, una por una, todas las capturas: miembros que no cargan, reportes de
Socios e Inteligencia, exports que no se generan, cuentas de recaudo que no se
guardan, mantenimiento que falla, "Error cargando configuración".

Arreglo inmediato:
```sql
ALTER TABLE gym_settings ADD COLUMN IF NOT EXISTS cash_shifts_enabled BOOLEAN NOT NULL DEFAULT true;
ALTER TABLE gym_settings ADD COLUMN IF NOT EXISTS tour_completed_at TIMESTAMP NULL;
```

### 2. El aligner de tenants no cubre 13 migraciones — SISTÉMICO
`app/db/tenant_align.py` es la única vía por la que una columna nueva llega a un
gym que ya existe (los tenants se bootstrapean con `create_all`, que jamás altera
tablas existentes, y el aligner cierra con `stamp head`, así que el cuerpo de las
migraciones nunca corre). Trece migraciones agregan columnas sin registrarse ahí:

`a1b2c3d4e5f6`, `a5b6c7d8e9f0`, `b0c1d2e3f4a5`, `b6c7d8e9f0a1`, `c1d2e3f4a5b6`,
`c4d5e6f7a8b9`, `c7d8e9f0a1b2`, `c9d0e1f2a3b4`, `d6e7f8a9b0c1`, `e7f8a9b0c1d2`,
`ef77a9a26fa3`, `f4a5b6c7d8e9`, `f8a9b0c1d2e3`.

Hoy solo duelen las de `gym_settings`; el resto se salvó por accidente de orden.
Cada release futura vuelve a romper a todo gym existente mientras esto siga así.

### 3. Producción no registra un solo log — ALTO
El archivo de log del contenedor lleva congelado en 888 bytes desde el 7 de
septiembre pese a estar sirviendo tráfico. Ni accesos ni errores: los 13 fallos
de arriba no dejaron una sola traza. Se diagnosticó todo desde afuera.
Sospecha principal: falta `PYTHONUNBUFFERED=1` en la imagen del backend
(el Dockerfile no lo define). Pendiente de confirmar.

### 4. Fechas corridas cinco horas en el panel — ALTO
El backend guarda `created_at` en UTC sin zona; el frontend hace
`new Date(created_at)`, que JavaScript interpreta como hora local. Después de las
7 pm de Bogotá, todo aparece con la fecha del día siguiente.

Verificado en vivo: socio registrado el 9/9 a las 8:45 pm, la lista dice
"Registro 10/9/2026".

Afecta 7 archivos: `MembersClient`, `MemberDetailClient`, `HistoryTab`,
`CashClient`, `payments/shared.ts`, `MachinesClient`, `Header`. En caja y pagos
descuadra contra los reportes, que sí usan hora de Bogotá.

### 5. Un fallo del almacenamiento se convierte en 500 sin manejo — MEDIO
Con MinIO caído, `EndpointConnectionError` sube sin capturar hasta el middleware.
El usuario ve un error genérico y el log (ver punto 3) no dice nada.

### 6. Herramientas de verificación desactualizadas — MEDIO
`scripts/e2e_test.py` falla en el primer paso: usa el payload viejo de socios
(sin `id_type`, `parq_answers`, `plan_id`). Da falsa sensación de cobertura.

### 7. Tope de paginación desalineado en socios — BAJO
`GET /members` corta en `le=100`. El frontend hoy no pide más, pero es la misma
trampa que ya explotó en Pagos (ahí ya está alineado en 200).

### 8. `MaintenanceLogCreate` exige `machine_id` en el cuerpo — COSMÉTICO
El id ya viaja en la ruta `/machines/{machine_id}/maintenance`. Duplicarlo
permite que cuerpo y ruta se contradigan.
